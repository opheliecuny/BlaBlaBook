# 6. Gestion des conflits Git dans VS Code

Mode opératoire pour récupérer une pull request en local, déclencher et corriger les conflits, puis pousser les modifications depuis **VS Code** avec **GitHub CLI (`gh`)** et **Git**.

---

## Prérequis

- **VS Code** installé et configuré avec l'extension **Remote - WSL** (si WSL2 est utilisé).
- **Git** et **GitHub CLI (`gh`)** installés et authentifiés.
- Un terminal intégré ouvert dans VS Code (`Ctrl + ~`).

---

## 1. Récupérer la Pull Request en local

### 1.1. Lister les PR disponibles

```bash
gh pr list
```

Repérer le **numéro** de la PR à récupérer.

### 1.2. Basculer sur la branche de la PR

```bash
gh pr checkout <NUMERO_PR>
```

Exemple :

```bash
gh pr checkout 42
```

Cela crée une branche locale avec le nom de la PR.

### 1.3. Vérifier la branche active

```bash
git branch
```

Un `*` doit apparaître devant le nom de la branche de la PR.

---

## 2. Mettre à jour les références distantes

### 2.1. Récupérer les dernières modifications de `main`

```bash
git fetch origin main
```

### 2.2. Vérifier l'état du dépôt

```bash
git status
```

---

## 3. Déclencher les conflits

### 3.1. Merger `main` dans la branche de la PR

```bash
git merge main
```

Si des conflits existent, Git les signale dans le terminal :

```
CONFLICT (content): Merge conflict in src/components/HomePage.tsx
Automatic merge failed; fix conflicts and then commit the result.
```

### 3.2. Localiser les fichiers en conflit

Dans le terminal :

```bash
git status
```

Les fichiers en conflit apparaissent sous **"Unmerged paths"**.

Dans **VS Code**, ouvrir l'onglet **Source Control** (`Ctrl + Shift + G`) — les fichiers en conflit sont marqués avec une icône **C**.

---

## 4. Résoudre les conflits dans VS Code

### 4.1. Ouvrir un fichier en conflit

Cliquer sur le fichier dans l'onglet **Source Control**. VS Code affiche les marqueurs de conflit :

```diff
<<<<<<< HEAD
// Tes modifications (branche de la PR)
=======
// Modifications de main
>>>>>>> main
```

### 4.2. Corriger le conflit

Modifier le fichier pour :

- Garder **ta version** (branche de la PR).
- Garder **la version de `main`**.
- **Combiner les deux** si nécessaire.

VS Code propose des raccourcis en haut du conflit : **Accept Current Change**, **Accept Incoming Change**, **Accept Both Changes**.

### 4.3. Marquer le fichier comme résolu

Après avoir enregistré le fichier (`Ctrl + S`) :

- Dans l'onglet **Source Control** → clic droit sur le fichier → **Stage Changes**.
- Ou en ligne de commande :

```bash
git add <fichier>
```

### 4.4. Répéter pour tous les fichiers en conflit

Résoudre les conflits un par un jusqu'à ce que `git status` n'affiche plus de **"Unmerged paths"**.

---

## 5. Finaliser la résolution

### 5.1. Commiter les modifications

```bash
git commit -m "fix: résolution des conflits pour la PR #<NUMERO_PR>"
```

### 5.2. Pousser les modifications

```bash
git push
```

---

## 6. Vérifier et merger la PR sur GitHub

### 6.1. Ouvrir la PR dans le navigateur

```bash
gh pr view --web
```

### 6.2. Vérifier les modifications

S'assurer que :

- Les conflits sont résolus.
- Les checks CI/CD passent.

### 6.3. Approuver et merger la PR

Approuver (si nécessaire) :

```bash
gh pr review --approve -b "Conflits résolus et validés."
```

Merger et supprimer la branche :

```bash
gh pr merge --merge --delete-branch
```

---

## Résumé des commandes

| Étape                   | Commande                                             |
| ----------------------- | ---------------------------------------------------- |
| Récupérer la PR         | `gh pr checkout <NUMERO_PR>`                         |
| Mettre à jour `main`    | `git fetch origin main`                              |
| Déclencher les conflits | `git merge main`                                     |
| Vérifier les conflits   | `git status`                                         |
| Résoudre un conflit     | Modifier le fichier dans VS Code                     |
| Marquer comme résolu    | `git add <fichier>`                                  |
| Commiter                | `git commit -m "fix: résolution des conflits PR #N"` |
| Pousser                 | `git push`                                           |
| Ouvrir la PR            | `gh pr view --web`                                   |
| Approuver               | `gh pr review --approve`                             |
| Merger                  | `gh pr merge --merge --delete-branch`                |

---

## Points d'attention

- **Tester** le code après résolution des conflits avant de pousser.
- **Communiquer** avec l'équipe si les conflits concernent une logique complexe ou partagée.
- **Vérifier les checks CI/CD** avant de merger (GitHub Actions doit être au vert).
