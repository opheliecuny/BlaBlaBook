# Mode opératoire : Mise en place des tests automatiques via GitHub Actions

Ce guide détaille les étapes pour configurer une **intégration continue (CI)** avec GitHub Actions afin d'exécuter automatiquement les tests à chaque Pull Request.

---

## Prérequis

- Dépôt Git hébergé sur GitHub
- Projet avec des tests configurés (frontend et/ou backend)
- Accès administrateur au dépôt GitHub

---

## Objectif

Mettre en place un workflow GitHub Actions qui :

1. S'exécute automatiquement à chaque **push** et **Pull Request** vers `main`
2. Lance les tests frontend (Next.js/React)
3. Lance les tests backend (Node.js/Express)
4. Bloque la fusion si les tests échouent

---

## Etape 1 : Créer la structure GitHub Actions

### 1.1. Créer le dossier `.github/workflows/`

A la racine de votre projet :

```bash
mkdir -p .github/workflows
```

### 1.2. Créer le fichier de workflow CI

Créer le fichier `.github/workflows/ci.yml` :

```bash
touch .github/workflows/ci.yml
```

---

## Etape 2 : Configurer le workflow GitHub Actions

Ouvrir le fichier `.github/workflows/ci.yml` et ajouter la configuration suivante :

```yaml
name: CI - Tests automatiques

# Déclencheurs : à chaque push ou PR vers main
on:
  push:
    branches:
      - main
  pull_request:
    branches:
      - main

# Définition des jobs (tâches)
jobs:
  # Job 1 : Tests Backend
  backend-tests:
    name: Tests Backend
    runs-on: ubuntu-latest

    # Etapes du job
    steps:
      # 1. Récupérer le code du dépôt
      - name: Checkout code
        uses: actions/checkout@v4

      # 2. Installer Node.js (version 20 LTS)
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: backend/package-lock.json

      # 3. Installer les dépendances backend
      - name: Install backend dependencies
        working-directory: ./backend
        run: npm ci

      # 4. Lancer les tests backend
      - name: Run backend tests
        working-directory: ./backend
        run: npm test

  # Job 2 : Tests Frontend
  frontend-tests:
    name: Tests Frontend
    runs-on: ubuntu-latest

    steps:
      # 1. Récupérer le code du dépôt
      - name: Checkout code
        uses: actions/checkout@v4

      # 2. Installer Node.js
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json

      # 3. Installer les dépendances frontend
      - name: Install frontend dependencies
        working-directory: ./frontend
        run: npm ci

      # 4. Lancer les tests frontend
      - name: Run frontend tests
        working-directory: ./frontend
        run: npm test

  # Job 3 : Lint (optionnel mais recommandé)
  lint:
    name: Vérification du code (ESLint)
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      # Lint Backend
      - name: Lint backend
        working-directory: ./backend
        run: |
          npm ci
          npm run lint --if-present

      # Lint Frontend
      - name: Lint frontend
        working-directory: ./frontend
        run: |
          npm ci
          npm run lint --if-present
```

---

## Etape 3 : Vérifier que les scripts de tests existent

### 3.1. Vérifier le fichier `backend/package.json`

Assurez-vous qu'il contient un script `test` :

```json
{
  "scripts": {
    "test": "jest",
    "lint": "eslint src/**/*.js"
  }
}
```

### 3.2. Vérifier le fichier `frontend/package.json`

Assurez-vous qu'il contient un script `test` :

```json
{
  "scripts": {
    "test": "jest",
    "lint": "next lint"
  }
}
```

**Note :** Si vous n'avez pas encore de tests, vous pouvez temporairement utiliser :

```json
{
  "scripts": {
    "test": "echo 'No tests yet' && exit 0"
  }
}
```

---

## Etape 4 : Commit et Push du workflow

### 4.1. Ajouter les fichiers au dépôt

```bash
git checkout main
git pull origin main
git checkout -b docs/github-actions-ci
git add .github/workflows/ci.yml
git commit -m "docs(ci): add GitHub Actions workflow for automated tests"
git push -u origin docs/github-actions-ci
```

### 4.2. Créer une Pull Request

1. Aller sur GitHub
2. Créer une Pull Request depuis `docs/github-actions-ci` vers `main`
3. Vérifier que les checks CI se lancent automatiquement
4. Si tout est vert ✅, fusionner la PR

---

## Etape 5 : Activer les protections de branche `main`

> ⚠️ **Note importante** : Cette fonctionnalité nécessite des permissions administrateur sur le dépôt.
> Sur les dépôts d'organisation (écoles, entreprises), cette option peut être désactivée par l'administrateur de l'organisation.
> Si l'option "Branches" n'apparaît pas dans les Settings ou si vous ne pouvez pas créer de règles, contactez l'administrateur de votre organisation.
> **Le workflow CI fonctionnera quand même**, mais la fusion ne sera pas bloquée automatiquement en cas d'échec des tests.

### 5.1. Accéder aux paramètres du dépôt

1. Aller sur GitHub → onglet **Settings**
2. Dans le menu de gauche : **Branches**
3. Cliquer sur **Add rule** (ou **Add branch protection rule**)

### 5.2. Configurer la règle de protection

| Paramètre                                     | Configuration recommandée     |
| --------------------------------------------- | ----------------------------- |
| **Branch name pattern**                       | `main`                        |
| **Require a pull request before merging**     | ✅ Coché                       |
| **Require approvals**                         | 1 (au moins un reviewer)      |
| **Require status checks to pass**             | ✅ Coché                       |
| **Status checks required**                    | Sélectionner tous les jobs CI |
| **Require branches to be up to date**         | ✅ Coché (recommandé)          |
| **Do not allow bypassing the above settings** | ✅ Coché                       |

### 5.3. Sauvegarder

Cliquer sur **Create** ou **Save changes**.

---

## Etape 6 : Tester le workflow

### 6.1. Créer une branche de test

```bash
git checkout main
git pull origin main
git checkout -b test/ci-verification
```

### 6.2. Modifier un fichier (par exemple, ajouter un commentaire)

```bash
echo "// Test CI" >> backend/src/index.js
git add .
git commit -m "test(ci): verify GitHub Actions workflow"
git push -u origin test/ci-verification
```

### 6.3. Créer une Pull Request

1. Aller sur GitHub
2. Créer une PR depuis `test/ci-verification` vers `main`
3. Vérifier que les **checks CI** apparaissent et s'exécutent
4. Attendre que tous les checks soient **verts** ✅

### 6.4. Résultat attendu

Vous devriez voir dans la PR :

```plaintext
✅ backend-tests — Passed
✅ frontend-tests — Passed
✅ lint — Passed
```

Si tout est vert, vous pouvez fusionner la PR. Sinon, corriger les erreurs signalées.

---

## Etape 7 : Workflow en cas d'échec des tests

### Scénario : Un test échoue

1. GitHub Actions signale l'échec dans la PR
2. Cliquer sur **Details** pour voir les logs
3. Identifier l'erreur
4. Corriger localement sur la même branche
5. Commit et push :

    ```bash
    git add .
    git commit -m "fix(tests): correct failing test case"
    git push
    ```

6. La PR se met automatiquement à jour et relance les tests
7. Une fois les tests passés, la PR peut être fusionnée

## Notes importantes

- **`npm ci`** est préféré à `npm install` en CI car il est plus rapide et reproductible
- Les workflows sont visibles dans l'onglet **Actions** du dépôt GitHub
- Chaque job peut être exécuté en parallèle pour gagner du temps
- Les logs complets sont disponibles dans l'onglet **Actions** pour déboguer les échecs

---

**Avec cette configuration, toute Pull Request devra passer les tests avant d'être fusionnée dans `main`, garantissant ainsi la qualité du code !** ✅
