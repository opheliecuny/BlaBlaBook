## 🗄️ Etape 1 : Déployer la Base de Données (Neon)

### 1.1. Créer le Projet Neon

1. Se connecter sur [Neon](https://neon.tech/) avec GitHub
2. Cliquer sur **"Create Project"**
3. Configuration :
   - **Project name** : `blablabook-db`
   - **Region** : `AWS Europe Central 1 (Frankfurt)` ou `AWS Europe West 2 (London)`
   - **PostgreSQL version** : `17` (pour correspondre au projet)
   - **Compute size** : `Shared` (gratuit)

4. Attendre la création (quelques secondes)

### 1.2. Récupérer les Informations de Connexion

1. Aller dans **Dashboard → Connection Details**
2. Copier la **Connection string** complète :

   ```plaintext
   postgresql://[user]:[password]@[host]/[database]?sslmode=require
   ```

   Exemple :

   ```plaintext
   postgresql://neondb_owner:AbCdEf123456@ep-cool-breeze-12345678.eu-central-1.aws.neon.tech/blablabook?sslmode=require
   ```

3. **⚠️ IMPORTANT** : Sauvegarder cette URL en lieu sûr

### 1.3. Tester la Connexion Localement

1. Créer un fichier `.env.production` dans `blablabook/backend` :

   ```env
   DATABASE_URL="postgresql://[copier URL Neon ici]"
   PORT=3000
   JWT_SECRET="[générer une clé secrète forte]"
   JWT_EXPIRES_IN="7d"
   ALLOWED_ORIGINS="https://blablabook.vercel.app"
   NODE_ENV="production"
   ```

2. Appliquer les migrations Prisma :

   ```bash
   cd blablabook/backend
   DATABASE_URL="[URL Neon]" npx prisma migrate deploy
   ```

3. Vérifier que les tables sont créées :

   ```bash
   DATABASE_URL="[URL Neon]" npx prisma studio
   ```

   Ouvrir <http://localhost:5555> et vérifier les tables `user`, `book`, `library_item`, `refresh_token`

### 1.4. (Optionnel) Seed la Base de Production

```bash
DATABASE_URL="[URL Neon]" npm run db:seed
```

## 🚀 Etape 2 : Déployer le Backend (Render)

> **ℹ️ Note importante** : Ce guide utilise l'approche **sans Dockerfile** (Runtime Node natif) car le projet utilise des modules ES (ESM) avec TypeScript, et `tsx` gère mieux cette configuration que `tsc`. Cette approche est plus simple et plus fiable pour ce projet.

### 2.1. Déployer sur Render

1. **Se connecter** sur [Render](https://render.com/) avec GitHub

2. **Créer un nouveau Web Service** :
   - Cliquer sur **"New +" → "Web Service"**
   - Connecter votre dépôt GitHub
   - Sélectionner la branche `main`

3. **Configuration du service** :

   | Paramètre          | Valeur                                          |
   | ------------------ | ----------------------------------------------- |
   | **Name**           | `blablabook-api`                                |
   | **Language**       | `Node`                                          |
   | **Branch**         | `main`                                          |
   | **Region**         | `Frankfurt (EU Central)`                        |
   | **Root Directory** | `blablabook/backend`                            |
   | **Build Command**  | `npm install && npx prisma generate`            |
   | **Start Command**  | `npx prisma migrate deploy && npx tsx index.ts` |
   | **Instance Type**  | `Free`                                          |

4. **Variables d'environnement** :

   Aller dans **Environment → Environment Variables** et ajouter :

   | Key               | Value                           | Notes                                  |
   | ----------------- | ------------------------------- | -------------------------------------- |
   | `DATABASE_URL`    | `[URL Neon complète]`           | Copier depuis Neon                     |
   | `JWT_SECRET`      | `[clé secrète 32+ caractères]`  | Générer avec `openssl rand -base64 32` |
   | `JWT_EXPIRES_IN`  | `7d`                            | Durée de validité des tokens           |
   | `PORT`            | `3000`                          | Port de l'application                  |
   | `ALLOWED_ORIGINS` | `https://blablabook.vercel.app` | À adapter selon URL Vercel             |
   | `NODE_ENV`        | `production`                    | Mode production                        |

5. **Créer le service** :
   - Cliquer sur **"Create Web Service"**
   - Attendre la fin du build (5-10 minutes)

6. **Récupérer l'URL du backend** :
   - Format : `https://blablabook-api.onrender.com`
   - **Copier cette URL** (nécessaire pour le frontend)

### 2.2. Tester l'API Déployée

1. **Vérifier les logs** :
   - Aller dans **Logs** sur Render
   - Chercher `🚀 Server started at http://localhost:3000`
   - Vérifier que les migrations Prisma se sont bien appliquées

2. **Tester avec curl** :

   ```bash
   # Health check (si implémenté)
   curl https://blablabook-api.onrender.com/health-check

   # Test inscription
   curl -X POST https://blablabook-api.onrender.com/auth/register \
     -H "Content-Type: application/json" \
     -d '{
       "email": "test@example.com",
       "password": "Password123",
       "confirmPassword": "Password123",
       "username": "testuser"
     }'
   ```

3. **Vérifier la base de données** :

   ```bash
   # Ouvrir Prisma Studio sur la DB Neon
   DATABASE_URL="[URL Neon]" npx prisma studio
   ```

   Vérifier que l'utilisateur de test a bien été créé

## 🌐 Etape 3 : Déployer le Frontend (Vercel)

### 3.1. Préparer le Frontend

#### Vérifier les Variables d'Environnement

Dans `blablabook/frontend/.env.local` (pour tests locaux) :

```env
NEXT_PUBLIC_API_URL=http://localhost:3000
```

⚠️ **NE PAS COMMIT** ce fichier (déjà dans `.gitignore`)

#### Vérifier `next.config.ts`

S'assurer que la configuration Next.js est optimale :

```typescript
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  // Optimisation pour production
  output: "standalone",

  // Images OpenLibrary
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "covers.openlibrary.org",
      },
    ],
  },
};

export default nextConfig;
```

### 3.2. Déployer sur Vercel

1. **Se connecter** sur [Vercel](https://vercel.com/) avec GitHub

2. **Importer le Projet** :
   - Cliquer sur **"Add New... → Project"**
   - Sélectionner votre dépôt GitHub
   - Cliquer sur **"Import"**

3. **Configuration du Projet** :

   | Paramètre            | Valeur                              |
   | -------------------- | ----------------------------------- |
   | **Framework Preset** | `Next.js` (détecté automatiquement) |
   | **Root Directory**   | `blablabook/frontend`               |
   | **Build Command**    | `npm run build` (par défaut)        |
   | **Output Directory** | `.next` (par défaut)                |
   | **Install Command**  | `npm install` (par défaut)          |

4. **Variables d'Environnement** :

   Ajouter dans **Environment Variables** :

   | Key                   | Value                                 | Environment |
   | --------------------- | ------------------------------------- | ----------- |
   | `NEXT_PUBLIC_API_URL` | `https://blablabook-api.onrender.com` | Production  |

   ⚠️ **Bien cocher "Production"** uniquement

5. **Déployer** :
   - Cliquer sur **"Deploy"**
   - Attendre la fin du build (2-5 minutes)

6. **Récupérer l'URL du frontend** :
   - Format : `https://blablabook-abc123.vercel.app`
   - Ou domaine personnalisé si configuré

### 3.3. Configuration CORS Backend

Mettre à jour la variable `ALLOWED_ORIGINS` sur Render :

1. Aller sur Render → Service `blablabook-api`
2. **Environment → Environment Variables**
3. Modifier `ALLOWED_ORIGINS` :

   ```plaintext
   https://blablabook-abc123.vercel.app
   ```

   Ou pour plusieurs origines :

   ```plaintext
   https://blablabook-abc123.vercel.app,https://blablabook.com
   ```

4. Sauvegarder → Le service redémarre automatiquement

### 3.4. Tester l'Application Complète

1. **Ouvrir l'URL Vercel** dans le navigateur
2. **Tester le flux complet** :
   - ✅ Inscription d'un nouvel utilisateur
   - ✅ Connexion
   - ✅ Recherche de livres (API OpenLibrary)
   - ✅ Ajout d'un livre à la bibliothèque
   - ✅ Changement de statut de lecture
   - ✅ Suppression d'un livre
   - ✅ Modification du profil
   - ✅ Déconnexion

3. **Vérifier la console navigateur (F12)** :
   - Pas d'erreurs CORS
   - Pas d'erreurs 401/403
   - Requêtes API passent bien

## 🔄 Etape 4 : Automatiser le Déploiement (CI/CD)

### 4.1. Configuration Actuelle

Le projet a déjà un workflow CI dans `.github/workflows/ci.yml` avec 5 jobs :

- `lint-backend`
- `test-backend` (73 tests avec PostgreSQL)
- `build-backend`
- `lint-frontend`
- `build-frontend`

### 4.2. Ajouter le Déploiement Automatique

Créer `.github/workflows/deploy.yml` :

```yaml
name: Deploy to Production

on:
  push:
    branches:
      - main
  workflow_dispatch: # Permet déclenchement manuel

jobs:
  # Job 1 : Déployer Backend sur Render
  deploy-backend:
    name: Deploy Backend (Render)
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Trigger Render Deploy Hook
        run: |
          curl -X POST ${{ secrets.RENDER_DEPLOY_HOOK_URL }}

  # Job 2 : Déployer Frontend sur Vercel
  deploy-frontend:
    name: Deploy Frontend (Vercel)
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '22'

      - name: Deploy to Vercel
        uses: amondnet/vercel-action@v25
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}
          working-directory: blablabook/frontend
          vercel-args: '--prod'
```

### 4.3. Configurer les Secrets GitHub

Aller dans **GitHub → Settings → Secrets and variables → Actions** :

#### Pour Render

1. Créer un **Deploy Hook** sur Render :
   - Aller sur Render → Service `blablabook-api`
   - **Settings → Deploy Hook**
   - Copier l'URL générée

2. Ajouter le secret :
   - **Nom** : `RENDER_DEPLOY_HOOK_URL`
   - **Value** : `[URL du deploy hook]`

#### Pour Vercel

1. Créer un **Access Token** sur Vercel :
   - Aller sur Vercel → **Settings → Tokens**
   - Créer un token avec scope "Full Access"

2. Récupérer les IDs du projet :

   ```bash
   cd blablabook/frontend
   npx vercel link
   # Suivre les instructions
   cat .vercel/project.json
   ```

3. Ajouter les secrets :
   - **`VERCEL_TOKEN`** : Token créé à l'étape 1
   - **`VERCEL_ORG_ID`** : `orgId` dans `.vercel/project.json`
   - **`VERCEL_PROJECT_ID`** : `projectId` dans `.vercel/project.json`

### 4.4. Tester le Workflow

```bash
# Pousser sur main
git add .
git commit -m "feat: setup automatic deployment"
git push origin main

# Le workflow se déclenche automatiquement
# Vérifier dans GitHub → Actions
```

- Endpoint à ping : `https://blablabook-api.onrender.com/health`

#### Vercel (Frontend)

- **Tableau de bord** : <https://vercel.com/dashboard>
- **Analytics** : Temps de chargement, requêtes
- **Logs** : Fonctions serverless

### 5.2. Sauvegardes Base de Données

#### Sauvegarde Manuelle

```bash
# Export complet de la base Neon
pg_dump "[URL Neon]" > backup-$(date +%Y%m%d).sql

# Compression
gzip backup-$(date +%Y%m%d).sql
```

#### Sauvegarde Automatique (GitHub Actions)

Créer `.github/workflows/backup.yml` :

```yaml
name: Database Backup

on:
  schedule:
    - cron: '0 2 * * *' # Tous les jours à 2h du matin
  workflow_dispatch:

jobs:
  backup:
    runs-on: ubuntu-latest
    steps:
      - name: Backup Database
        run: |
          pg_dump "${{ secrets.DATABASE_URL }}" > backup.sql

      - name: Upload to GitHub Releases
        uses: actions/upload-artifact@v4
        with:
          name: database-backup-${{ github.run_number }}
          path: backup.sql
          retention-days: 30
```

Ajouter le secret `DATABASE_URL` (URL Neon) dans GitHub Secrets.

## ⚠️ Points d'Attention

### Limitations Free Tier

| Service    | Limitation                    | Impact                                | Solution                              |
| ---------- | ----------------------------- | ------------------------------------- | ------------------------------------- |
| **Neon**   | Base s'endort après 5 min     | Première requête lente (~2s)          | UptimeRobot ou passer au plan Pro     |
| **Render** | Service s'endort après 15 min | Démarrage à froid ~30s                | UptimeRobot ou passer au plan Starter |
| **Render** | 750h/mois gratuit             | Service peut s'arrêter en fin de mois | Surveiller l'usage                    |
| **Vercel** | 100 GB bandwidth/mois         | Dépend du trafic                      | Optimiser images, CDN                 |

### Sécurité

- ✅ **HTTPS** : Activé par défaut sur Vercel et Render
- ✅ **Cookies httpOnly** : Déjà configuré dans le code
- ✅ **CORS** : Configuré via `ALLOWED_ORIGINS`
- ✅ **Helmet** : Déjà activé dans Express
- ⚠️ **JWT_SECRET** : Utiliser une clé forte (32+ caractères aléatoires)

Générer une clé secrète forte :

```bash
openssl rand -base64 32
```

### Performance

#### Backend (Render)

- `tsx` compile TypeScript à la volée (JIT) avec un overhead minimal
- Prisma Client est généré pendant le build pour optimiser les performances
- Les dépendances sont mises en cache par Render entre les builds

#### Frontend (Vercel)

- Images OpenLibrary : déjà optimisées via `next/image`
- `output: 'standalone'` : réduit la taille du bundle
- CDN Vercel : distribution mondiale automatique

## 🆘 Troubleshooting

### Erreur : "Database connection failed"

**Symptôme** : Backend ne démarre pas, logs Render montrent erreur Prisma

**Solutions** :

1. Vérifier `DATABASE_URL` dans Render (copié correctement depuis Neon)
2. Vérifier que `?sslmode=require` est présent
3. Tester la connexion localement :

   ```bash
   DATABASE_URL="[URL]" npx prisma migrate deploy
   ```

### Erreur CORS : "Access-Control-Allow-Origin"

**Symptôme** : Frontend ne peut pas appeler l'API, erreur dans console navigateur

**Solutions** :

1. Vérifier `ALLOWED_ORIGINS` sur Render contient l'URL Vercel
2. Vérifier que l'URL Vercel est exacte (pas de `/` à la fin)
3. Vérifier les logs Render pour voir les requêtes

### Frontend affiche des erreurs 401

**Symptôme** : Impossible de se connecter, toutes les requêtes retournent 401

**Solutions** :

1. Vérifier que `JWT_SECRET` est identique à celui utilisé lors du register
2. Vérifier les cookies dans DevTools (F12 → Application → Cookies)
3. Vérifier que les cookies sont `httpOnly` et `secure`

### Service Render ne redémarre pas

**Symptôme** : Modifications poussées mais backend ne se met pas à jour

**Solutions** :

1. Vérifier que le commit est bien sur `main`
2. Vérifier le deploy hook dans GitHub Actions
3. Redémarrer manuellement : Render Dashboard → Manual Deploy
