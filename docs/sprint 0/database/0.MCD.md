# MCD - Modèle Conceptuel de Données

Dans un MCD, on se concentre sur les entités, leurs propriétés et les relations (avec leurs cardinalités), en évacuant les détails techniques de clés étrangères qui appartiennent au niveau logique (MLD).
Les **entités** représentent les objets principaux du système. Chaque entité a des propriétés (ou attributs) qui la décrivent.

## 1.Les Entités et leurs Propriétés

### UTILISATEUR

- email
- mot de passe
- pseudo

### LIVRE

- ISBN
- openLibraryId (identifiant de l'API Open Library)
- titre
- auteur
- genre littéraire
- description
- image de couverture
- éditeur
- nombre de page
- langue
- date de publication

---

## 2. Les relations et Cardinalités

Les **relations** décrivent comment les entités interagissent entre elles.
Les **cardinalités** indiquent le nombre minimal et maximal de liens possibles.

### Relation : POSSEDE

Cette relation associe un **UTILISATEUR** à un **LIVRE** avec des informations supplémentaires sur cette association.

- Propriétés de la relation :
      - statut : Etat du livre dans la bibliothèque de l'utilisateur (ex : "A lire", "En cours", "Lu")
      - note : Note attribuée par l'utilisateur (de 1 à 5, optionnel)
      - commentaire : Avis personnel sur le livre (optionnel)
      - date_ajout : Date à laquelle le livre a été ajouté à la bibliothèque
      - date_modification : Date de dernière modification de l'entrée

- Cardinalités :
      - Un **UTILISATEUR** peut posséder **0 à N livres** (un utilisateur peut ne pas avoir de livres ou en avoir plusieurs).
      - Un **LIVRE** peut être possédé par **0 à N utilisateurs** (un livre peut ne pas être dans la bibliothèque de personne ou être référencé par plusieurs utilisateurs).

---

## Code MOCODO

```mocodo
UTILISATEUR: email, mot de passe, pseudo
POSSEDER, 0N UTILISATEUR, 0N LIVRE: statut, note, commentaire, date_ajout, date_modification
LIVRE: ISBN, titre, auteur, genre littéraire, description, image de couverture, éditeur, nombre de page, langue, date de publication
```
